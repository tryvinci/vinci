# OLF movie engine (`vinci-olf`)

**Build the world once. Render every episode.** A game engine runs a scene file. This engine runs a show written in the **Open Lore Format (OLF) v0.1**: a bible (style, characters, locations, props, voices), then seasons (optional), episodes, scenes and shots. It renders takes from them, and it tells you which takes are out of date.

Each render is slow, gives a different result each time, and can cost money. So the core of the engine works like a build system: a shot is a target, `inputs_hash` is the cache key, a take is the output, and a stale take needs a new render.

Status (2026-11-09): **Reader** conformance level, plus the **Renderer** level for shots (keyframe, video and dialogue takes, keyframe variations, batch renders for an episode; COREPRODUC-541), a CLI, daemon routes, and the Studio **Shows** page. COREPRODUC-542 adds most of the **Full** level: the cut list and export (16:9 and 9:16 with burned-in subtitles and separate dialogue, after a license check) in the engine and the Studio Cut screen. Music and SFX cues wait for a runtime capability (COREPRODUC-551). Other follow-ups: see [Limits](#limits-and-follow-ups). COREPRODUC-564 (2026-11-10) adds **Camerawork**: engine moves (a video from the chosen keyframe with no video model, $0), durations in seconds+frames (`3+12`), and camerawork templates (a bible kind, with a CC0 library of anime templates). COREPRODUC-565 adds **previs** (the e-conte sheet and the animatic, $0), pills and the 180° line, pans and tilts across a larger drawing (`camera.canvas`), and the library grows to 32 of the 36 planned templates.

## Commands

All commands take `-C <project folder>` (default: the current folder) and `-v` (logs and tracebacks).

```bash
./scripts/vinci olf validate -C packages/olf/conformance/tidewatch
./scripts/vinci olf resolve e02/s03/sh014 -C packages/olf/conformance/tidewatch [--kind keyframe|video|audio]
./scripts/vinci olf render e02/s03/sh014 -C <copy of the project> [--kind keyframe|audio] [--count 1-4] [--model ID] [--keyframe-model ID] [--yes] [--dry-run]
./scripts/vinci olf render e02/cue/theme -C <project> [--model ID] [--yes] [--dry-run]   # a music or SFX cue take
./scripts/vinci olf batch e02 --stale | --animate-approved -C <project> [--yes] [--dry-run]
./scripts/vinci olf status [e02/s03] -C <copy of the project>
./scripts/vinci olf review e02/s03/sh014/v1 --status approved [--notes "Slight flicker at 3.5s"] -C <project>
./scripts/vinci olf select e02/s03/sh014 --keyframe kf2 [--video v1 | --video none] -C <project>
./scripts/vinci olf cut e02 [--use-approved] -C <project>
./scripts/vinci olf export e02 [--aspect 16:9] [--aspect 9:16] [--no-subtitles] [--c2pa] [--otio] [--no-sound] -C <project>
./scripts/vinci olf template [anime/tu-to-eyes] [--shot e02/s03/sh014] -C <project>
./scripts/vinci olf previs e02 [--sheet] [--animatic] [--mock] -C <project>
```

- `validate` prints errors and warnings. Exit code 1 when there is an error.
- `resolve` prints the resolved view of a shot and its `inputs_hash` per take kind. With `--kind`, it prints what that kind hashes.
- `render` prints the plan and the price, then writes `takes/<shot>/kf<N>.png`, `v<N>.mp4` and their take files, and adds the new assets to `assets/lock.yaml`. `--kind audio` speaks the shot's dialogue into `a<N>.wav`. `--kind keyframe --count 3` draws three keyframe variations, each its own take. `--dry-run` prints the plan only: nothing is staged, run or written. A paid total, or a live model with no flat price (amount 0 on a provider other than mock: per-token billing), needs `--yes`.
- `batch` renders for a whole episode, shot after shot in play order, after one price check for the batch (see "How batch renders work"). `--stale` makes new takes where the current take is stale; `--animate-approved` makes a video from each approved keyframe that has none. `--dry-run` prints the jobs and the total only.
- `status` lists takes: kind, status (`draft`, `candidate`, `approved`, `rejected`), and `fresh` or `stale`.
- `review` sets a take's `status` and `notes`. `select` picks the takes a shot uses (`none` clears one). Each edit changes one line, and the rest of a hand-written file stays byte for byte (comments, spacing, `{ key: value }` style). The edit is parsed again before it is saved.
- `cut` prints the episode's cut as a timeline (start, take, kind, trims, transition, fresh or stale). `--use-approved` first writes the cut from approved takes in play order: a shot's approved video (the chosen one first), else its approved keyframe, which plays as a still.
- `export` writes `exports/<episode>/<episode>-16x9.mp4`, `-9x16.mp4` and `<episode>.srt`. It runs local ffmpeg only: no model runs and nothing costs money. `--no-sound` writes the files with no audio stream (no take sound, dialogue, music or SFX): the lines are only subtitles, and each subtitle names its speaker (`Mira: You kept the key?`).
- `template` with no ID lists the camerawork library (ID, family, `engine $0` or `model`, default length, name), with a `*` on each template the show has a copy of. With an ID it copies that template into the show's bible (`bible/camerawork/<slug>/<slug>.yaml`, ID `cam/<slug>`, with its `source`). With `--shot` it also puts the template on the shot: `camera.template`, the default length, and no move fields of the shot's own.
- `previs` writes `previs/<episode>/<episode>-sheet.pdf` with its PNG pages, and `<episode>-animatic.mp4`. With no flag it makes both. `--mock` writes `<episode>-mock.mp4`, the mock render: every shot from its pills, no sound, the lines as subtitles. It runs local Pillow and ffmpeg only: $0 (see "How previs works").
- A duration in a file or on the command line can be seconds (`4s`) or seconds+frames (`3+12`: a frame is 1/24 s). `render` prints a `note` when an engine move enlarges its keyframe.
- Errors print one line and exit with code 2.

`vinci olf` needs no daemon. The CLI starts `python3 -m vinci_olf`, which runs the runtime `Engine` in-process on `$VINCI_HOME` (default `~/.vinci`), as `python -m vinci_harness demo` does. Run `vinci init --demo` first for $0 renders.

## Studio: the Shows page

**Shows** is on the Studio rail (Workflows: Canvas, Shows, Library) and in All tools / Ctrl+K. It talks to the daemon routes below, so the CLI, the Studio and later MCP use one engine.

**The Claude Design editor is the reference.** The page follows its structure and behaviour as closely as possible, in the Studio look (cyan accent, Inter Tight, Instrument Serif titles), so Shows stays consistent with the other Studio pages. The design's own header becomes the Studio top bar, and the design's amber accents become the Studio's cyan. Where the design shows a control that the engine cannot do yet, the page leaves it out and the gap has a Plane item (see COREPRODUC-541, 542, 543, 545, 547, 548, 549).

The flow is keyframes first: **the bible locks the look, the storyboard reviews keyframes (cheap stills), and the shot page draws keyframes, approves them and renders video from the chosen keyframe.** Stale takes are calculated, never stored: an orange `stale` mark means an input changed after the render.

- **Open:** **New show**, open the sample show (the daemon copies `tidewatch` into `$VINCI_HOME/shows/` once), a show from **Your shows** (`GET /olf/shows`), or type a show folder. Recent shows stay in `localStorage` (`vinci-shows-recent-v1`). The newest one opens again on the next visit, on the storyboard of its first episode. On a host (see [On a host](#on-a-host-vinci-platform)) there is no folder box and no recent paths.
- **Top bar** (`ShowTop` in `shows-nav.tsx`, rendered into the `.top-shows` slot of the Studio top bar): the crumb (`Tidewatch / E02 · The Second Light`, or `Bible · Characters · Mira Sol`), then the spec (or the entry's YAML file on a bible page), a health pill (`Valid OLF v0.1` or the error count; it opens the issues page), Reload, the design's **Share** (the show as one `.olf.zip`) and Close show. The design's Credits is the Studio's own ≈ $ meter. On the shot page: `‹ Storyboard / e02/s03/sh014` with the take status and stale mark, and the previous and next shot.
- **Left panel** (`ShowNav`): the sections as a list (Bible, Storyboard, Shots, Cut), then the episodes by season (episodes in no season come last, under Episodes), and the design's **+ New episode** (it joins the last season). In the Bible: Style, Characters, Locations, then Props · Voices. The shot page and the Cut screen have no left panel and use the full width, as in the design.
- **Storyboard** (`shows-storyboard.tsx`): the header has the design's batch buttons: **Re-render N stale** (in the stale colour) and **Animate approved · est. $X**. Both come from dry runs of `POST /olf/batch` for the episode; the tooltip lists each job and why. A paid batch, or one with a model that has no flat price, asks "Spend $X on N renders?" once. The Studio then runs the batch one job per `POST /olf/render`, each job bounded by its planned price (`runJobs` in `shows-api.ts`), so no request outlives the proxy. A whole episode in one request did, in the live test of 2026-11-09. The notice counts the jobs (`Rendering 2 of 6: e01/s01/sh020 · video…`), the card of the running job shows what it renders, the board reloads after each job, and a higher price stops the rest. Then four counts (shots, keyframes approved, stale takes, runtime), then each scene with its heading, location, variant and cast looks (`Mira Sol (winter, night outfit)`). Each scene ends with the design's dashed **+ Add shot** card (what happens, length, framing); **+ Add scene** follows the last scene, and an episode with no scenes asks for its first scene. A card shows the shown keyframe (`select.keyframe`, else the newest) with its status at the top left and the stale mark at the top right, and words such as `kf1 · v1 approved`. The cards are for review: a card opens its shot page. A card and a Shots row show the length as seconds+frames (`4+00`, `2+12`), the notation of storyboards (COREPRODUC-564).
- **Shot page** (`shows-shot.tsx`): a stale banner as in the design: it explains the take on screen (else the first stale take), for example `Stale: the outfit "night" of char/mira (description) changed after v1 was rendered`, with **See change** (each changed field, before and now) and **Keep v1 anyway**; the current take with the design's play bar (play, scrub, `1.5 / 4.0s`; it drives the video, or the dialogue of an audio take), take cards (keyframes, then videos, then dialogue; a chosen take has a cyan outline), and provenance with Approve and Reject. After a render, the page shows the render's first new take, even when another take was clicked before; Approve then acts on the new take. **Approve also chooses the take** (`select.keyframe`, `select.video` or `select.audio`), as the design outlines approved takes as selected; a second click sets it back to draft. A dialogue take card shows its length; when it is the current take, its audio plays over the shot's picture. The right column shows the description and camera as fields, as in the design: the description (saved on blur) and the framing, angle, lens (from `style.lenses`) and move menus each write one line of the file that holds the shot (`vinci_olf.author.set_shot`); each character with `form: winter · from episode` and `outfit: night · from scene` (the `origins` of `vinci_olf.api.shot_detail`), blocking, dialogue with **Render dialogue** (the voice model and its price under it), the scene's location and mood, and the render panel: the video model menu (`Auto · <routed model>`, then each connected model with its price; a pick changes the price, the confirm and the bound), the estimated cost, **Keyframes per draw** (1 to 4 variations, each its own take), **New keyframe** and **Render video** (Re-render video once a video exists). For a shot with `control.first_frame: keyframe`, video is on only when a keyframe is chosen. A paid render, or one with a model that has no flat price, asks "Spend $X?" first. "What the engine sends next" (folded) shows the references (whole files), the prompt and the hashes. **Camerawork** (COREPRODUC-564) is a menu above the camera fields: the show's own templates, then the library by family (`Track up to the eyes · T.U. · Engine $0 · 3+00`). A pick copies a library template into the bible, sets `camera.template`, gives the shot the template's default length and removes the shot's own move fields (`POST /olf/camerawork`); the template's intent and a link to its bible page show under the menu. The camera grid also has **Length** (seconds+frames or seconds), **Render** (`model` or `engine`), **Amount** and **Ease**. A field that the template fills is marked `· template`; a value typed on the shot goes in the shot's own line and wins. With Render on `engine`, the render box shows `Engine move · $0` in place of the video model menu, the hint says `The engine moves the chosen keyframe kf1`, and a note warns when the move enlarges the keyframe (`plans.video.notes`). `hold_start`, `hold_end` and `center` have no control yet: they are set in the YAML file.
- **Bible pages** (`shows-bible.tsx`): the name and description, and a `Used in N shots · M episodes` pill. Left: the character sheet and a Details grid (detail images and textures, each a separate file), or the style look, or the references. Right: forms with their front view, palette and shot count; outfits; variants; lenses and negative words; and the Linked panel (entry IDs, design credit, license from the lock file or from `project.yaml` before the first render, and the edit impact: `Editing the description, a form or an outfit makes 2 takes stale. Credits and license edits do not.`). A voice without a name shows as `Mira's voice`. A character's Linked panel has a **Voice** menu: the ElevenLabs account's voices (`GET /olf/voices`, a free call). A pick writes the voice entry (`POST /olf/voice`), and the dialogue takes in the old voice go stale. Without ElevenLabs the menu says to connect it, because demo speech has one voice. **Clone from sample** (COREPRODUC-559) makes a new voice from a recording (MP3, WAV, OGG or FLAC, at most 20 MB) with ElevenLabs Instant Voice Cloning (`POST /olf/voice/clone`). The person must tick "I have the right to use this voice, and the speaker agreed to the clone" before anything is sent. The clone comes first, so a refused clone writes nothing. Consent covers one clone: each close of the form (Cancel or a made clone) drops the recording and the tick. If the show cannot save a made clone, the error names that voice, so it is picked in the Voice menu, not made again. Then the recording becomes the voice entry's `sample` (`sample-<content hash>.<ext>`, a new file per recording), with a lock entry, and the character speaks in the new voice. The entry switches to a new recording only once it is saved; then the replaced sample and its lock entry go. ElevenLabs wants at least 10 s of clean speech (1 to 2 minutes is best), and each clone takes a voice slot of the account. The character sheet panel has a tab per sheet when a character has more than one, and **+ Sheet**. The whole sheet is the character reference: there are no regions or crops, and no region detection (decisions 2026-11-09). **Replace sheet** acts on the sheet shown and writes the new image under its file name, so the character file does not change; takes that used the old sheet become stale. **+ Form** adds a form with its description, palette and front view (`forms/<name>/front.png`). The project view gives each bible file a short content hash, so a replaced image loads again. Other entry fields are edited in the YAML file that the top bar names. **Camerawork** (COREPRODUC-564) is a fourth group in the Bible list. A template's page shows its camera (render, move, amount, ease, holds), what it suits (length, framing, cast, rules), its words for the model, its source (`A copy of anime/tu-to-eyes@1 from the camerawork library (CC0)`, and the library's newer version when there is one), `Used in N shots`, and the edit impact (`Editing the camera, the prompt words or the avoid words makes 1 take stale`).
- **Cut** (`shows-cut.tsx`, design screen 4): the sections become tabs in the top bar, next to `episodes/e02/episode.yaml · cut`. The 16:9 preview and its 9:16 crop (the same center crop as the export) show the clip under the playhead with the subtitle line. Playback runs in the browser over the take files (a clock walks the clips), so nothing renders before Export. The transport has the time, **Use approved takes** (a shot whose chosen dialogue take is approved plays it as separate sound), and **Add music cue** (COREPRODUC-551): Music or SFX, a description, a length (music up to 60 s, a sound effect up to 30 s), a volume and Duck under dialogue (on for music); **Add at 0:01.0** prices the cue first (a paid cue or a model with no flat price asks once), then renders it and places it at the playhead (`POST /olf/cue`). The timeline has a ruler, the Video track (clips sized by length; `kf only`, `fade`, `stale` and `missing` marks), the Dialogue track (the design's `a1 · Mira Sol` block under each clip that plays separate dialogue, as long as the speech; `stale` when the take speaks an old line), the Music · SFX track (the design's `Slow piano · a1 · vol 0.6 · ducked` block from the cue's start, as long as its take; `stale` when the cue changed), and the playhead; a click seeks or selects a clip. A fade looks like the export: for its 0.5 s, the clip that fades in covers the clip before it, more each frame (`fadeAt`; each clip plays at its own time in its take). Playback sounds like the export: the wide preview plays the take's own sound, or the separate dialogue from the start of its clip, and each cue plays from its start at its volume (the browser caps volume at 1; ducking is heard only in the export). The Export panel has the design's **C2PA provenance** (on when the daemon has `c2pa-python`) and **Also export OTIO and stems**; the file list links each MP4 and WAV. The selected clip has In, Out, Transition in (Cut / Fade) and Audio (the take's own sound, or `Separate dialogue take (a1)`: the shot's `select.audio`). Export has 16:9 at the project resolution, 9:16 at 1080×1920 for X, and burn-in subtitles; C2PA provenance and "OTIO and stems" stay off (COREPRODUC-544). A stale or missing clip shows a warning, and so does a clip that plays separate dialogue with no chosen dialogue take (Export stays off); Export episode lists the written files. With no cut yet, the page offers Use approved takes.
- **New show** (`shows-setup.tsx`, design screen 5; COREPRODUC-547): three steps. **Show**: title, medium and aspect. **First character**: name, description, a sheet (the whole sheet is the reference) and a voice (the same Voice menu). **First episode**: the script box (Fountain or plain text, **Import .fountain**, **Draft from idea**, **Split with a model**) beside the shot list the rules make from it (`sh010 · WS · 24mm · text · 2.5s`, scene by scene), with the design's notices for new locations and new characters. The footer says `2 keyframe options per shot · est. $X`. **Create show and draw keyframes** writes the show (`POST /olf/new`) and runs the `keyframes` batch (two keyframes per shot, price first: a paid total or a model with no flat price asks once). A script with a speaker the bible does not know creates that character without a sheet, so the button reads **Create show** and draws nothing: render stays off until the sheet is added. **Skip to an empty project** writes only the show. The new show opens on the storyboard of episode 1.
- **Shot list from script** (Storyboard header; COREPRODUC-548): the same script panel, for the open show. The shot list uses the show's bible names (`MIRA` -> `char/mira`, `LAMP ROOM` -> `loc/lighthouse`), and **Add N scenes · M shots to E01** writes them (`POST /olf/script`). New locations and characters are added to the bible as in New show.
- **Shots** (`ShotsTable` in `shows-storyboard.tsx`): one row per shot of the episode in play order, with the camera, length, keyframe status and takes. The design names this section but has no screen for it.
- **States:** off (the daemon has no `/olf` routes), open, wrong folder, invalid (a banner, Render off, an issues list; a shot that cannot resolve shows the engine's reason on its page), loading, rendering, notices.
- **Tokens** (`app/theme.css`): `--stale`, `--stale-soft` and `--stale-line` for the orange mark; `--status-approved`, `--status-candidate` and `--status-rejected` for take status; `--font-mono` for IDs and hashes.

## Daemon routes

`create_app` mounts `apps/daemon/vinci_daemon/olf_routes.py` only when `vinci_olf` imports (`pip install -e "apps/daemon[olf]"`; `make install` installs it). The Studio checks `/openapi.json` for `/olf/project` before it calls them, so a build without the engine shows the off state and no 404s.

| Route | Does |
| --- | --- |
| `GET /olf/shows` | The shows in `$VINCI_HOME/shows` (`path`, `title` from `project.yaml`, `updated_at`), last changed first, for the open screen |
| `POST /olf/sample` | Copy the sample show into `$VINCI_HOME/shows/tidewatch` once; return its folder |
| `GET /olf/project?path=` | The whole show as JSON (`vinci_olf.api.summary`): issues; bible entries with their file, assets, usage, edit impact, license and (characters) shots per form; seasons; episodes with each scene's cast looks; shots; takes with `stale` |
| `GET /olf/shot?path=&shot=` | Resolved view, `origins` (the level that set each field), hashes, prompts, references, and a dry-run plan per render kind (`video`, `keyframe`, `audio`; a shot without dialogue gets an `error` plan for audio). Each plan lists `choices`: the connected models for its last step, cheapest first (the model menu) |
| `GET /olf/share?path=` | The show folder as `<show>.olf.zip` (design: Share). `exports/` and `previs/` are left out, and a link that leaves the show is skipped |
| `POST /olf/previs` | The e-conte sheet (`sheet`), the animatic (`animatic`) and/or the mock render (`mock`) of an `episode` in `previs/<episode>/`: `{files, cuts, runtime}`. $0. `GET /olf/file` serves the PDF |
| `POST /olf/render` | Render (or `dry_run`) a keyframe, video or `audio` take. `max_total` is the price a person confirmed: a plan above it stops. 409 while the durable journal is on |
| `POST /olf/batch` | Batch render an episode (`mode`: `stale`, `animate` or `keyframes`), or `dry_run` for its jobs and total. `max_total` bounds the batch as for render. 409 while the durable journal is on |
| `POST /olf/new` | Create a show in `$VINCI_HOME/shows/<title>` (`-2`, `-3` when taken): `project.yaml`, `bible/show.yaml`, `bible/style.yaml`, the first character with its sheet, the sheet's lock entry and its voice (`character.voice_id`), and episode 1 from `script`. A failed create removes the folder |
| `GET /olf/voices` | The voices a character can speak in: the ElevenLabs account's voices (`provider: elevenlabs`; a free call), or none without ElevenLabs |

## How a shot resolves

The engine merges up to six levels, top to bottom (SPEC.md, Layering and overrides):

1. **Project defaults**: `defaults` and `extensions` from `project.yaml`.
2. **Show bible**: the style, as `style`.
3. **Season**: when a season file (`seasons/NN.yaml`) lists the episode, the same fields an episode may set. Its title, synopsis and episode list are structure. An episode in no season skips this level.
4. **Episode**: only `defaults`, `forms`, `outfits`, `style` and `extensions`. Title, scenes and the cut list are structure, not overrides, so an edit to the cut never makes a take stale.
5. **Scene**: every field except `shots`.
6. **Shot**: every field.

Order: a season lists its episodes in play order, an episode lists its scenes in play order, and shots play in shot-number order (`sh010`, `sh015`, `sh020`). Episode IDs stay unique in the whole show, so seasons can come later without renaming episodes. In the sample, `season/01` sets grain `medium` (it applies) and outfit `default` (scene `s03` overrides it with `night`).

Merge rules: scalars and lists replace; maps merge key by key; `{ $append: [...], $remove: [...] }` edits the list from the level above.

Then the engine embeds the bible entries that the shot uses:

- `location` becomes the location entry with the chosen `variant` (the `variants` list goes).
- Each character gets only its chosen `form` and `outfit`. When no level chooses one, the one named `default` applies. Its `voice` becomes the voice entry.
- `props` become prop entries.
- `credits`, `license` and `likeness` go, because they never change a render.
- Each asset reference becomes its full asset ID (`asset/<64 hex>`, the SHA-256 of the file). A reference names a whole file: `sheet.png#eyes` is an error.
- Durations become numbers of seconds (`4s` and `4.0s` both become `4`).
- A duration in seconds+frames becomes seconds too (`3+12` and `3.5s` both become `3.5`), as do `camera.hold_start` and `camera.hold_end`.
- `camera.template` (COREPRODUC-564): the camerawork template fills only the camera fields that no level states (`resolve._camerawork`). `camera.template` then holds the template's `id` and its words for the prompts (`keyframe`, `prompt`, `avoid`). Its other fields change no render, so they stay out. `origins` gives each camera field its origin in `camera_fields`: a level, or the template's ID.

## How staleness works

A take stores `inputs_hash`. The engine calculates the current hash each time it reads the project and compares the two. It never stores `stale` (SPEC.md, Status values). The hash covers only what the take kind uses (SPEC.md, Hash input):

| Take kind | Hashes | Leaves out |
| --- | --- | --- |
| Keyframe | the resolved shot | `select`, `duration`, `camera.move`, `camera.direction`, `camera.amount`, `camera.ease`, `camera.hold_start`, `camera.hold_end`, `camera.center`, `camera.render`, the template's `id`, `prompt` and `avoid`, `dialogue`, `audio`, `control.first_frame`, `control.last_frame`, character voices |
| Video | the resolved shot, with each `keyframe` control replaced by the output of the keyframe take it used | `select` |
| Audio (dialogue) | `id`, `dialogue`, and the `id` and `voice` of each speaker | everything else |

The canonical JSON follows RFC 8785. It matches the `rfc8785` reference library on the three sample shots and the RFC Appendix B number cases (checked 2026-11-08).

Effects, tested on the sample: an edit to a character description or a sheet image makes both takes stale. An edit to `credits` or `select` makes neither stale. An edit to the camera move or a dialogue line makes only the video stale. With a template (COREPRODUC-564): an edit to its `intent`, `timing` or `rules` makes nothing stale; an edit to its camera, `prompt` or `avoid` makes only the videos of its shots stale; an edit to its `keyframe` words makes their keyframes stale too. A new template on a shot does not make its keyframe stale. A video of an engine move hashes the output of the keyframe it moved, also when the shot has no `control.first_frame`.

## How render works

1. Resolve the shot.
2. Pick the reference images (at most 8): each character's form front view, else every sheet of the character (whole files), else its first other reference; then the first reference of each prop, the location, and the style references. A node sends the first as `image` and all of them as `image_urls`; fal, Higgsfield and Wavespeed's Seedream and Nano Banana Pro edit routes read all of them.
3. Write a model-agnostic prompt from the resolved shot: framing, angle, lens, description, characters with form, outfit and blocking, location and variant, props, style look and mood. A video prompt adds the camera move and the dialogue. The style `negative` list goes in `negative_prompt`. A camerawork template adds its words after the description: `keyframe` to a keyframe prompt, `prompt` to a video prompt, with `{a}`, `{b}`, `{c}` as the names of the shot's characters in order. Its `avoid` words join the `negative_prompt` of the video node only.
4. Build an inline workflow:
   - **Keyframe** node: `i2i` with the references (`image` is the first one, `image_urls` has all of them), or `t2i` when there are none.
   - **Video** node: `i2v` from the keyframe when `control.first_frame` is `keyframe`, `i2v` from an asset when it names one, else `t2v`.
   - With `select.keyframe` set, the video animates from that take and no new keyframe renders. Otherwise a new keyframe renders first. The engine never writes `select`: picking a take is a human choice.
   - **Variations** (`--count N`, keyframes only, 1 to 4): N keyframe nodes (`keyframe`, `keyframe2`, ...), each with its own take ID, so the price is N keyframes.
   - **Dialogue** nodes (`--kind audio`): one `tts` node per dialogue line (`line1`, `line2`, ...), with the line as the prompt. The run joins their audio in order into one take, with 0.3 s of silence between lines (`vinci_media.join_audio`: mono 48 kHz WAV).
   - **Engine move** (`camera.render: engine`, COREPRODUC-564): the video node is a `media` node with the op `camera_move`, not a model node. It moves the frame over the keyframe (the chosen one, else a new one from the keyframe node; or the file that `control.first_frame` names) with the shot's `move`, `direction`, `amount`, `ease`, `hold_start`, `hold_end`, `center` and `canvas`, at the project resolution and fps, for the shot's exact number of frames. A still can do `static`, `push_in`, `pull_out`, `pan`, `tilt`, `truck` and `shake`; another move stops the plan (`the engine cannot make a orbit move from a held drawing`). The plan row is `local:ffmpeg:v1` at $0, so nothing asks for `--yes`, and no provider must be connected. The take is a normal video take: `provider: local`, no `prompt`, the move in `parameters`, and its length to the millisecond (`0.750s`). The plan has `notes` when the move enlarges the keyframe more than 1.25 times (a push shows the size of the drawing). Render does not validate the show first, so the plan checks what the move reads: the camera fields against the schema, and the frame against the limits of `vinci_media.camera.check` (16 to 4096 px a side, 1 to 60 fps, up to 120 s), because each frame is an image in memory. `defaults.fps` can be a fraction (23.976).
5. Plan the workflow, then pin each node to its planned model. The video node asks for a clip length the model takes (`fit_duration` in `vinci_core.cost`; the runtime uses the same rule for any job's `duration`): the shortest of the catalog's `durations` that covers the shot (a 4 s shot asks Kling 2.6 for 5 s), else the longest; a model with only `max_duration` gets the shot length rounded up, capped there. The take records the real length (ffprobe), and the cut trims a longer clip. Then add `extensions.<provider>` of that model's provider as parameters: the speaker's voice entry first (for example `voice/mira` with `elevenlabs: { voice_id: ... }`), then the shot's levels. A core parameter (prompt, images, duration) always wins over an extension, and an extension cannot set the clip length or the number of outputs (`duration`, `seconds`, `num_frames`, `n`, `num_images`, `num_outputs`, `num_videos`, `batch_size`; SPEC.md rule 4), because the price check could not see them. The plan lists the keys each node gets from extensions (`vinci olf render` prints them). Other provider settings, such as a resolution, can still change a provider's price.
6. Check the price with the runtime cost engine. A render that costs more than $0 stops unless you pass `--yes`. `extensions.x-router.prefer` sets the routing preference (`cheapest`, `fastest`, `quality`). `max_cost_usd` sets the run budget.
7. Run it with `Engine.start_run(workflow=...)`. Each node gets a Vinci-only `olf_take` param (providers send only the params they know). It makes each take a new generation, not a $0 replay of the last identical request.
8. Check each keyframe and video with the palette check (`vinci_olf.qa`): the take's twelve main colors against the palettes of the shot's character forms. Each palette color counts by how close the nearest main color is (an RGB distance of 120 counts as missing); 0.6 passes. It writes `qa: [{ check: palette, score, pass }]` (the Studio shows `QA palette 0.82 pass`). It is a cheap signal that a render kept the forms' colors, not a likeness check: no identity model runs locally.
9. Write each output to `takes/`, write its take file with provenance (provider, model, prompt, parameters, created, cost) and `inputs_hash`, and add the outputs and the input files to `assets/lock.yaml` with the license from `project.yaml`. Existing lock entries and their comments stay as they are. An audio take records the lines it spoke as its prompt (one per line), its length as `duration`, and the cost of all its lines.

`render` is three steps a host can also call apart (COREPRODUC-588): `plan_render` (steps 1 to 5: the price, and a JSON job with the nodes, the resolved view and the reference files), the price check and the run, then `record_render` (steps 8 and 9, from the outputs' bytes and receipts). The local runtime joins them in one call.

The sample renders at $0 in demo mode: `mock:png:v1` for the keyframe, `mock:mp4:v1` for the video, and `mock:wav:v1` for dialogue (a WAV hum about as long as the line, with a pitch per voice). Each mock take is a new picture (the mock seeds by take, as a real model gives a new image for each call), so variations differ. The sample art is flat placeholder boxes, so live renders of the sample are not useful.

## On a host (Vinci Platform)

The hosted Studio on app.tryvinci.com runs these pages on its own backend (`apps/vinci-backend`, COREPRODUC-588). The pages are the same; a host differs here:

- **Paths:** a show is `show:<id>`, never a folder. `GET /olf/shows` lists the user's shows.
- **Fewer routes in v1:** no speech, music, sound effects, voices, previs or share. The Studio hides a control when `/openapi.json` does not list its route (`OlfRoutes` in `shows-api.ts`): Share, Add music cue, the Voice field and the previs buttons.
- **Prices in credits:** `host.currency` is `credits`, so `price()` shows credits (`setShowsCredits`). The host plans with `vinci_core` on a catalog in credits (`Catalog.currency`).
- **Long steps answer at once (HTTP 202):** `POST /olf/render` gives `run_id`, and the Studio polls `GET /runs/{id}` until the run ends and its takes are recorded (`olf.recorded`). `POST /olf/export` gives `export_id`, and the Studio polls `GET /olf/exports/{id}`. `olf()` waits for both, so callers get the finished answer. `GET /olf/project` lists the renders still running (`renders`), so a reload polls them again.
- **Media stays in storage:** the host builds the show folder per request with empty stand-ins for media and passes their hashes to `load(root, hashes=...)`, so no media is read; a project file only changes on a write.

## How batch renders work

`vinci_olf.batch.render_batch` renders for a whole episode (COREPRODUC-541):

1. List the jobs, in play order (`jobs`):
   - `stale`: for each kind (keyframe, video, audio), the current take is the selected one, else the newest. When it is stale and no fresh take of that kind waits beside it, the shot gets a new take of that kind. A video waits while the chosen keyframe it animates from is stale: the new keyframe needs a person's choice first. Dialogue that was removed is not spoken again.
   - `animate`: a video for each shot that animates from a keyframe, whose chosen keyframe is approved and fresh, and that has no fresh video made from it. A shot with `camera.render: engine` counts as one that animates from its keyframe (`resolve.from_keyframe`), and its job costs $0.
   - `keyframes`: two keyframes (variations) for each shot that has no keyframe yet. New show runs it after it writes the show.
2. Plan each job with a dry run and add the prices. One price check covers the whole batch: a paid total, or a model with no flat price, needs `--yes`. The Studio sends the total it confirmed (`max_total`), and a batch that costs more stops.
3. Run the jobs one after another (synchronous). Each job loads the project again, so it sees the takes that the jobs before it wrote, and it may not cost more than its planned price. A job that fails gets its `error`; the other jobs still run. A shot that does not resolve gets an `error` and is not rendered.

The engine never writes `select`, so a batch never picks a take: new keyframes, videos and dialogue wait as drafts for a person to approve them.

## How scripts become shots

`vinci_olf.script` (COREPRODUC-547, -548). The rules need no model:

1. A scene heading (`INT.`, `EXT.`, `INT./EXT.`, `I/E`, `EST`, or a forced `.HEADING`) starts a scene. `PLACE - TIME` gives the location and the variant (`dusk`). Text before the first heading, or a script without headings, is one scene. The title page, transitions (`CUT TO:`), centered text, notes and the boneyard are skipped.
2. A character cue (a line in capitals with text under it, or `@Name`) starts a dialogue line; a parenthetical becomes `delivery`. Each other paragraph is action, split into sentences.
3. Each action sentence and each dialogue line is one shot, numbered in steps of 10. The first shot of a scene is wide (24mm), other actions are medium (35mm), a line is a close-up (50mm), and a lens is set only when the style lists it. A line lasts about 2.5 words a second plus 0.5 s (1.5 to 8 s); an action about 3 words a second plus 1 s (2 to 6 s), rounded to 0.5 s.
4. A paragraph that starts with a shot tag, `[WS 24mm 4s] The lamp turns.`, is one shot with that framing (`EWS WS MS MCU CU ECU INS`), lens and length.
5. A cue matches a bible character by name, first name or slug; a place matches a location by name or slug, and its variant is kept only when the location lists it. A known character named in the action is in the scene (so its sheet is a reference). Others become new entries: a location gets a text description and the times it is used at as variants; a character gets a description and needs a sheet (the validator says so).
6. `import_script` checks every new file against the OLF schema before it writes any, and refuses to overwrite a file. The scene keeps its script text (without tags) in `script`.
7. Each imported scene sets `control: { first_frame: keyframe }`: its shots animate from the chosen keyframe, and Animate approved finds them. A dialogue shot's description names the action only (`Mira whispers.`). The line stays in `dialogue`, because an image model draws a quoted line in the description as a caption. Both were found in the live test of 2026-11-09 (COREPRODUC-558).

Text-model steps (`t2t`, a runtime capability since COREPRODUC-548) run like a render: plan, price, then `Engine.start_run` with one node. **Split with a model** sends the script with instructions to answer in tagged Fountain; the answer is parsed by the same rules. **Draft from idea** asks for a short Fountain script. The catalogs have `openai:gpt-6-luna:2026-11` (Responses API) and `google:gemini-3.8-flash:2026-09` (`generateContent`); both bill by token, so they have no flat price and every step asks first (COREPRODUC-533). In demo mode `mock:llm:v1` answers with the `mock_reply` the engine sends (the rules' own tagged list, or a one-scene draft of the idea), so a $0 run takes the same path.

An installed agent CLI can do both steps: Claude Code, Codex, Antigravity (`agy`), Cursor Agent or OpenCode (`vinci_provider_sdk/agent_cli.py`). The script box has a **Text model** menu (`GET /olf/models`): Auto (routing) and each connected model, with "your plan" for a CLI. The Studio keeps the last pick in local storage. A CLI bills the person's own sign-in, so its model (`claude_code:cli`, currency `PLAN`) is never routed automatically: it runs only when picked, and the step still asks first ("Write a draft with Claude Code? It runs on your own Claude Code sign-in and bills that account. Vinci adds no charge."). The CLI runs once in print or exec mode in a new empty folder, with its tools off where it has a flag for that, and Vinci reads its final answer (each CLI's flags: VINCI_OSS_RUNTIME.md). A script can carry instructions for the agent, so for each CLI that keeps some tools (all but Claude Code), the question adds: "It can use its own tools, such as reading your files: use it only with scripts you trust." The live-spend switch does not apply, because Vinci sends no request of its own. The Mac app forces it off, and CLIs still run there.

## How export works

`vinci_olf.export.export` assembles takes that exist (COREPRODUC-542, phase A):

1. Read the cut (`cut_view`): each clip's take, file, trims (`in`, `out`; a keyframe take plays as a still for its shot's duration, and a video take plays for its shot's duration too unless the row sets `out`), transition and start on the timeline. A fade starts 0.5 s before the clip before it ends.
2. Stop when the cut is empty, when a take file is missing, when a clip plays separate dialogue but its shot has no chosen dialogue take with a file, or on licenses: every asset in the cut (each take's output, the references it used, each separate dialogue take, and each music and SFX take) needs a license with `owner` and `terms` in the lock file, and terms that forbid derivatives (`ND`) stop the export.
3. Bring each clip to the project format (`defaults.resolution`, `defaults.fps`; fit and pad), with stereo sound: the take's own (silence when it has none), or with `audio: separate` the shot's chosen dialogue take, from the start of the clip, ending in silence (COREPRODUC-542, phase C). Then join the clips (`concat`, or `xfade` and `acrossfade` for fades).
4. Lay the audio list over the joined sound (`vinci_media.mix_cues`, COREPRODUC-551): each music or SFX take starts at its `start` (`adelay`) at its `volume`; with `duck_under_dialogue`, ffmpeg `sidechaincompress` keyed by the episode's own sound makes it quieter while the dialogue plays. A cue take with no file stops the export.
5. Build subtitles from shot dialogue: each line gets an equal share of its clip's time. Write them as `<episode>.srt`, and burn them into each file as caption images drawn with Pillow and laid over the video with ffmpeg's `overlay`. This works with any ffmpeg build: Homebrew ffmpeg has neither `drawtext` nor `subtitles` (libass).
6. Write the 16:9 file (the project frame) and the 9:16 file (a center crop at 1080 x 1920, `vinci_media.reframe_9x16`) to `exports/<episode>/`. Exports are derived output: they are not added to the lock file.
7. With `c2pa` (COREPRODUC-544; SPEC.md: engines SHOULD), sign each MP4 last: a C2PA manifest with a `c2pa.created` action (AI-generated media) and an `org.tryvinci.olf` assertion that lists the show, the episode and each take the file shows (ID, model, provider, created, license). The signer is local: a CA and an ES256 signing certificate made on first use in `$VINCI_HOME/c2pa/` (the key is readable by its owner only). A reader sees a valid signature from a certificate that is not on the C2PA trust list.
8. With `otio`, also write `stems/<episode>-dialogue.wav` (the cut's own sound, with separate dialogue, before the music), `-music.wav` and `-sfx.wav` (each kind of cue at its start and volume, not ducked), and `<episode>.otio`: OpenTimelineIO JSON written without the library. It has a Video track (each clip with its trims; a fade is an `SMPTE_Dissolve` centered on the cut, so the clips still add up to the cut), a Dialogue track, and one audio track per music or SFX row (a gap, then the cue take, with its volume and ducking as metadata). Media references are the take files, relative to the export folder. OpenTimelineIO 0.18.1 reads it with the same length as the cut (checked 2026-11-09).

## How previs works

Cookbook: [From a script to an anime episode](https://docs.tryvinci.com/learn/anime-episode-from-a-script) walks a person through the whole process, from a new show to an export with no sound, with the episode of these runs as its example output.

`vinci_olf.previs.previs` (COREPRODUC-565) makes two outputs of an episode, at $0, in `previs/<episode>/`. They are derived output, as exports are: not in the lock file, not in the Share zip, made again on request.

1. **Pills** (`vinci_olf.layout.staging`). Each shot gets its pills: the shot's `layout`, else its template's, else one pill per character at the head size and eye line of its framing (`HEADS`). In a scene, a shot whose template has `rules.sets_axis` fixes the side of each character. A shot with no layout keeps each character on its side; a layout that swaps two of them, or a single that looks away from the others, gets the warning "Crosses the 180° line" (the validator). A pill looks at its `look_at` pill, else as stated, else at the other pills of the frame; a single looks toward the side of the line where the others are, and with no stated `x` it sits 0.1 from the centre, behind its gaze (look room). A pill has its character's color in each shot (`COLORS`, by the order of the bible), whatever its slot there.
2. **The best picture of a shot** (`best_take`): its chosen take of a kind (`select`), else its newest take of that kind that is not rejected. Video first, then keyframe, then pills.
3. **The e-conte sheet** (`write_sheet`): an A4 page (150 dpi) for each 5 cuts, as PNG pages and one PDF (Pillow; no new dependency). Columns: Cut (`C-001`, the place in play order, and the shot ID), Picture (the whole drawing with the frame marks of the move: the first window solid, the last window dashed, an arrow for a pan, a tilt or a truck), Action (description, template, framing and move), Dialogue (`MIRA: line`), Time (`3+00`). Each page ends with its time and the running total; the last page adds the cut count and the runtime (`0:08+12`).
4. **The animatic** (`write_animatic`): one MP4 of the episode in play order, 960 px wide at the project fps. Each shot plays for its length: its video (from 0), else its keyframe under its camera move (`camera_move`; a move that a still cannot do holds), else its pill clip (`pill_frames`: the pills go from `start` to `end` under the camera move, with its holds and fairing, over a grid that shows the move). The shot's chosen dialogue take is its sound.
5. **The mock render** (`write_mock`, `--mock`): the same cuts and timing as the animatic, but every shot from its pills for its whole length, under its camera move, at the same review frame. No shot mixes in a model take, a clip of another shape or a sound of its own, so the cuts look the same. There is no sound; each line is a subtitle with the speaker's first name (the lines of a shot share its time). It writes one silent video in one pass, then burns the subtitles.
6. **Canvas.** `camera.canvas` (`21:9`, `9:16`, ...) is the shape of a drawing larger than the frame. A keyframe render asks the model for that shape (`aspect_ratio`); a model whose catalog entry lists other shapes stops at the plan. On a shot with a canvas, a pan, a tilt or a truck with no `amount` goes from one edge of the drawing to the other (`vinci_media.camera.windows`, `canvas=`); a 16:9 frame can pan 0.31 frame widths over 21:9 and tilt 2.16 frame heights over 9:16. Where the drawing has too little room, the window gets smaller by the travel, as before. A shot with no canvas moves inside the centre crop, as before canvases, also over a keyframe of another shape (a square keyframe in a 16:9 show tilts 0.2 frame heights): the same take inputs give the same move.

## Spec changes made with Slice 1

These edits to `SPEC.md` (2026-11-08) close gaps found while building the engine:

1. The five override levels are written as text. The PDF had them only in a diagram.
2. `select` is out of every hash. A video take hashes the output of the keyframe take it used (`inputs.first_frame`), so picking takes never makes a take stale.
3. Each take kind hashes only the fields it uses (table above).
4. An asset reference becomes its full asset ID. (Crops kept their region here until change 12 removed them.)
5. When no level chooses a form or an outfit, the one named `default` applies.
6. "Engines MUST NOT add values that no file states" replaces "default values", which could be read as "do not merge project defaults".
7. `project.yaml` has an optional `license`: the default license for assets that the engine adds to the lock file.
8. A relative `uri` in `lock.yaml` is relative to the project folder. Anywhere else, a relative path is relative to the file that holds it.
9. The Character example quotes the outfit descriptions (see Bugs fixed).
10. Seasons: an optional level between the bible and the episode. `seasons/NN.yaml` (ID `season/NN`) lists its episodes in order and may set the overrides an episode may set. An episode is in one season at most.
11. Cut and export (COREPRODUC-542): a cut clip may set `audio: own | separate` (separate = the shot's `select.audio` dialogue take); a fade overlaps the clip before it; a keyframe take in the cut plays as a still; subtitles come from shot dialogue, each line getting an equal share of its clip's time; exports go to `exports/<episode>/` and stay out of the lock file.
12. Sheets (COREPRODUC-545, decisions 2026-11-09): the whole sheet is the character reference. A character may list more whole sheets (`sheets: [sheet-ember.png]`); form views and details are optional separate files. `regions` and `#crop` references are gone (a `#` reference is an error), and engines do not detect regions. A form with no front view sends every sheet.
13. Stale takes explained and kept (COREPRODUC-549): engines MAY keep a take's hash view in `takes/<take>.inputs.json` to say which fields changed; a person MAY keep a stale take, and the engine then records the replaced hash in `kept_from`.
14. Music and SFX cues (COREPRODUC-551): an episode lists its cues under `cues` (`theme: { kind: music, description, duration }`, the cue `e02/cue/theme`). A cue take hashes the cue (`id`, `kind`, `description`, `duration` in seconds), so it is stale when the cue changed. A scene or shot `audio` (`sfx`, `music`) must name cues of its episode.
15. Durations (COREPRODUC-564): a duration can be seconds+frames (`3+12`), with a frame of 1/24 s in each project. It normalizes to seconds before the hash.
16. Engine moves (COREPRODUC-564): `camera.render` (`engine` or `model`), `camera.amount`, `ease`, `hold_start`, `hold_end`, `center`, and the move `shake`. Keyframe takes leave them out of their hash. A video of an engine move hashes the keyframe it moved. A take that no model made records the engine's own name as provider and model.
17. Camerawork (COREPRODUC-564): a bible kind, `cam/<slug>`, that a shot names in `camera.template`. It fills only the camera fields that no level states. The resolved view keeps its `id`, `keyframe`, `prompt` and `avoid`. A library template is used through a copy in the show's bible.
18. The cut (COREPRODUC-564): a video take plays for its shot's duration unless the clip sets `out`.
19. Layout and the 180° line (COREPRODUC-565): `layout` (pills at `start` and `end`) on a shot or a template, in no hash; the template rules `sets_axis`, `max_per_scene` and `needs_prop`.
20. Canvas (COREPRODUC-565): `camera.canvas`, the shape of a drawing larger than the frame. Keyframe takes hash it.
21. Previs (COREPRODUC-565): `previs/<episode>/` is derived output, as `exports/` is.

Engine choices that the spec leaves open:

- `extensions` inherit from the manifest and the episode like other fields.
- A scene can state any shot field (`camera`, `props`, `control`, ...) for all its shots.
- Schemas reject unknown fields, so a typo such as `discription` is an error. Extra data goes under `extensions`.
- A relative path that leaves the project folder is an error, because a project can come from someone you do not trust.
- `extensions.<namespace>` becomes model parameters when the namespace is the Vinci provider ID of the planned model (`elevenlabs`, `fal`, `wavespeed`, `mock`, ...). The speaker's voice entry comes first, then the shot's levels; core parameters win. Other namespaces (`x-router`, model families such as `kling`) are not sent.
- A shot's dialogue is one audio take: one speech request per line, joined in order with 0.3 s between lines.
- A separate dialogue take plays from the start of its clip and is not trimmed with the clip's `in`; the clip's own sound is not mixed in.
- A script paragraph that starts with `[FRAMING LENS SECONDSs]` is one shot (the format a text model answers in). The scene's `script` keeps the text without tags. "Use approved takes" sets `audio: separate` when the shot's chosen dialogue take is approved.

Fix: a failed plan stops the render with `OlfError` ("no connected model can render this keyframe (no model for i2i)"), and the shot page shows it per kind.
- **The bible page crashed for a character with no forms** (first occurrence, found 2026-11-09 by the PR-Agent review of #525 before merge; 0 user reports). The Forms panel shows on every character since + Form (COREPRODUC-543), and it called `Object.entries(data.forms)` with `undefined`. Each character that New show creates has no forms. Fix: an empty map. The New show e2e test now opens that character.
- **A failed keyframe batch in New show made a second show on retry** (first occurrence, PR-Agent on #525; 0 user reports). The wizard created the show, and when the batch then failed (for example "the price changed"), the wizard stayed open. Each retry made `title-2`, `title-3`. Fix: the show opens anyway, and the notice says why no keyframes were drawn.
- **A failed cue render left its cue in `episode.yaml`** (first occurrence, PR-Agent on #525; 0 user reports). `/olf/cue` lists the cue first, so a provider error left a cue with no take, and each retry added `-2`, `-3`. Fix: the route puts the old `episode.yaml` back when the render fails.
- **A failed Share left a temp zip** (first occurrence, PR-Agent on #525; 0 user reports). Only the response removed the file, so an error while zipping (a full disk) kept it. Fix: the route removes it on any error.
- **The clone form kept the consent tick after it closed** (first occurrence, found 2026-11-10 by the CodeRabbit review of #528 before merge; 0 user reports). `CloneVoice` stays mounted when it closes, so the recording and the tick survived Cancel and a made clone, and the next **Clone from sample** opened ready to send another recording. Fix: every close clears both; the Shows e2e reopens the form after Cancel.
- **A clone that could not reach ElevenLabs gave a bare HTTP 500** (first occurrence, CodeRabbit on #528; 0 user reports). `POST /olf/voice/clone` turned only an `HTTPError` into a readable 400. No network, a timeout, a missing key or an answer with no `voice_id` reached the Studio as "Internal Server Error". Fix: these become `ElevenLabs could not clone the voice: <reason>`, and the daemon logs the cause.
- **A clone reference over 25 MB was cut short and sent** (first occurrence, CodeRabbit on #528; 0 user reports). A `voice_clone` job read at most 25 MB of an https `reference` and sent that part, with no error. Fix: a larger reference is refused, downloaded or a `data:` URI (`MAX_REFERENCE` in the ElevenLabs plugin; the second CodeRabbit pass found the `data:` case). Allowing only public hosts for that URL is COREPRODUC-560.
- **A clone that the show could not save was not named** (first occurrence, the second CodeRabbit pass on #528; 0 user reports). When writing the sample, its lock entry or the voice entry failed after the clone was made, the error did not say that a clone existed, so a retry made another one and held another voice slot. Fix: the error names the voice and its ID: reload and pick it in the Voice menu, or delete it in ElevenLabs. The clone is not deleted, because the voice entry may already point to it.
- **A failed save after a clone could pair the old voice with the new recording** (first occurrence, the third CodeRabbit pass on #528; 0 user reports). A new clone overwrote `sample.<ext>` before the voice entry changed. If the save then failed, the entry kept the old voice ID with the new recording, and the lock matched the new bytes, so validation could not see it. Fix: each recording gets its own file (`sample-<content hash>.<ext>`). The entry switches to it only after the save, and only then the old sample and its lock entry go. Only file names that `clone_voice` writes are removed, because project files can be untrusted.
- **A replacement sample could get a stale lock hash** (first occurrence, the third CodeRabbit pass on #528; reproduced: 1 lock error after a replacement on a validated project). `Project.sha256` caches hashes by path, so on a project that was validated first, the overwritten `sample.<ext>` kept its old hash, and the new lock entry failed the next validation. Fix: the new file per recording (above), so a cached hash never describes overwritten bytes.
- **`make install` failed on Linux CI after the C2PA export** (recurring: every Vinci OSS CI run since #525, 2 runs on the release PR #519; 0 user reports). The pin `c2pa-python>=0.38.2` has macOS wheels only, so pip on Linux found no version, and the free gate and the clone smoke stopped at Install. Local runs passed because they ran on macOS. Fix: `>=0.38.1`, the newest release with Linux wheels, in the Makefile and in the `vinci-olf[c2pa]` extra.
- **A wrong `select` shape crashed the Cut view** (first occurrence, found 2026-11-09 in a self-review of COREPRODUC-542 phase C before push; 0 occurrences in use). `dialogue_take` read `select.audio` without a type check, so `select: [a1]` gave HTTP 500 on `/olf/cut` instead of an issue. Fix: a `select` that is not a map has no dialogue take; the issues page reports the shape.
- **Demo speech was text, not audio** (first occurrence, found 2026-11-08 while planning COREPRODUC-541; 0 user reports). `mock:txt:v1` answered `tts` with JSON text bytes, which the runtime stored as an audio asset that no player could play. Fix: the new `mock:wav:v1` answers `tts` with a real WAV; `mock:txt:v1` keeps `transcribe`, `sts` and `voice_clone`.
- **`vinci olf` without `python3` crashed with a Node stack trace** (first occurrence, PR-Agent on #517). Fix: an `error` handler prints one line and exits with code 2.
- **A late image load could set the wrong size** (first occurrence, PR-Agent on #517). `useNaturalSize` could apply the size of the previous URL after the URL changed. Fix: the effect ignores loads after its cleanup. (`useNaturalSize` went with the crops on 2026-11-09.)
- **Form thumbnail drawn as a thin line** (first occurrence, found 2026-11-08 in the editor screenshots before merge; 0 user reports). The ember form's front view is an `<img>` with `max-width: 100%` in an `auto` grid column. The percentage has no width to resolve against, so the column shrank to the image border. Fix: `.olf-look > .ref-thumb { max-width: none; }`. Rule: no percentage `max-width` on an image in an `auto` grid track.

- **Shows gaps found by the production Studio crawl** (first occurrence, 2026-11-13, COREPRODUC-642; 0 user reports). (1) The Shots table and the cards showed only the last part of a shot ID, so `e01/s01/sh010` and `e01/s02/sh010` both read "sh010". The IDs were unique (numbers restart per scene, as the spec allows); `shotLabel` now shows `s02/sh010`. (2) "+ New episode" showed its notice before the reload, and an older `/project` answer (a render poll) could land after the new one; `open()` now keeps only the newest load (a failed older load cannot clear a newer show), a reload never replaces a show being opened or another show on screen, and the success notice comes after a good reload (a failed reload keeps its own notice). (3) A show with errors locks the storyboard, but Add shot, Add scene and the script button were off with no reason; a line on the page and each control's `title` now say "Fix them on the Issues page". (4) "Split with a model" left the free rules preview on screen before Confirm and after a refusal, so it looked like the model's split; while a model split waits or after a refusal the list is hidden and Add stays off until the text changes (a rules preview that lands after the split started does not turn Add on). A second click on Add while the first one wrote added the scenes twice; Add is off while it writes. The host now refuses a free plan before the price (`text_step`). (5) "Add scene" in an empty episode was off with no reason; the text says to write the heading first, and the button's `title` says so. The wizard keeps its draft for the tab (`vinci-new-show-draft-v1`).
