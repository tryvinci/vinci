# Vinci OSS Runtime

> **Vinci** — the open-source generative media runtime. Bring your own API keys, use any supported model/provider, and run portable generation/editing/clipping workflows with transparent cost and routing.

This file is the architecture contract. Do not invent a second architecture.
Executable gates live in `VINCI_OSS_E2E_ACHIEVEMENT.md`.

**Meeting anchor:** Aug 26 L'Oreal/Shiva sync — Engram/Vinci as open-source workflow layer; users bring Google/etc. API keys; Magnific/Higgsfield compete on workflow, not unique models. Cost transparency is the wedge.

## 2. System shape

CLI + Studio → Daemon (HTTP + worker + MCP) → Runtime → Plugins + Cost engine + Media + local CAS/SQLite.

Language split: Python for protocol/core/runtime/providers/media/index/MCP; TypeScript for CLI + Studio.

Local-first defaults: SQLite + CAS under `~/.vinci/cas/`. No Mongo/Redis/Docker/account for the default path.

Proprietary never lands here: Clerk, Dodo/credits, Mongo user ledgers, hosted vault, marketing pages, enterprise moderation ops.

## 3. Protocol

`vinci-protocol` ships JSON Schemas + Pydantic/TypeScript types: Asset, ModelSpec, Job, WorkflowSpec, Receipt, Event, Timeline (Phase 3), error taxonomy (`auth`, `quota`, `rate_limit`, `invalid_input`, `content_policy`, `provider_down`, `timeout`, `cancelled`, `unknown`).

`ModelSpec.constraints.durations` lists the exact clip lengths (seconds) a video model takes, from the provider's API docs; empty means any length up to `max_duration`. The Studio Video page shows only those tiles, and the OLF engine fits each shot to them. The Wavespeed and fal video rows have lists (checked 2026-11-09); the Google, Magnific and Higgsfield rows whose provider takes only some lengths have them since 2026-11-13 (COREPRODUC-635). Rows that take any whole length in a range (Kling 3, Wan 2.7) and the Higgsfield DoP and Seedance 1 rows (no longer in docs.higgsfield.ai, not checked) have only `max_duration`. Google lists every Gemini API Veo 3.1 model as shut down on 2026-10-22 (ai.google.dev deprecations); the `google:veo-3.1-*` rows are not checked with a key (COREPRODUC-635, retired rows: COREPRODUC-553).

Job states: `created → awaiting_approval → queued → running → completed | failed | cancelled`.

`protocol_version` handshake. Current: `0.1.0`.

## 4. Provider plugin SDK

`Provider` ABC: `catalog`, `capabilities`, `estimate`, `submit`, `status`, `cancel`, `normalize_error`.

Conformance: schema round-trips, estimate-before-submit, error normalization, idempotent status polling, secret-free logging. A plugin is not listed until it passes.

Credential resolution: providers declare secret **names**; `vinci-core` resolves keychain → `$VINCI_HOME/keys/` (mode 0600) → env → config refs. Studio can paste a key; the raw value never lands in git, jobs, receipts, or logs.

MVP providers: Wavespeed, Google, fal, ElevenLabs, Cloudflare, **Higgsfield**, **Magnific / Freepik**. Mock ships in the SDK. Higgsfield auth is key **and** secret (`Authorization: Key id:secret`). Magnific auth is `x-magnific-api-key`. Catalogs are curated allowlists from public API docs (Higgsfield OpenAPI, Magnific `llms.txt` / changelog, fal app IDs) — not the full vendor gallery, and **not MCP-only**. **MCP is a custom provider type**, not the only extension — paste a URL when you want an external MCP backend (including a vendor MCP such as Magnific MCP).

Catalog: curated versioned allowlist JSON; `vinci catalog refresh` produces a reviewable diff, never a silent live mutation. **Sora is excluded** from the default catalog (API sunsets 2026-09-24).

## 5. Cost engine

Pre-run estimate, budgets/approvals, immutable receipts, cheapest-compatible routing, pricing snapshots, CAS/idempotency replay at $0, skill cost metadata. An accepted run pins every generate node to the model its estimate used (`accept_run`), so the approved estimate stays valid when the mode changes mid-run. If that model leaves the catalog (its provider turns off, or a catalog update removes it), the node fails with "<model> is not in the catalog now" and does not move to another model.

Replay at $0 needs the row's current pricing snapshot: a result made under an older row (another price, or another request from the plugin) runs again, and the newest result is the one reused. So change a row's `snapshot_at` whenever its price or what the plugin sends for it changes (COREPRODUC-596).

Clip length: a row whose provider bills by length lists `clip_prices`, the price of each clip length it takes, in seconds, from the provider's page (`{"5": 0.35, "10": 0.7}`). The plan (`plan_workflow`, also for a `{{inputs.duration}}` param), the job estimate and its receipt, the OLF render plan, the Studio Video page and the canvas price the clip length the model makes (`fit_duration` of the ask). The canvas reads a node's `{{inputs.duration}}` from the inputs the run sends, a skill preview applies the skill's input defaults, and the cheaper alternative shown with an estimate is priced at the same length. `amount` stays the price of the default clip, and ranks the row. A row without a table is one price per job: on 2026-11-11 the Wavespeed and fal video rows list one (COREPRODUC-555, COREPRODUC-603; Higgsfield and Magnific bill credits, COREPRODUC-598; music and speech: COREPRODUC-603).

Speech, music and sound effects: a row whose unit names a measure is billed by it, as `amount × measure ÷ size`: `1k_chars` by the job's text (`prompt` or `text`, also an `{{inputs.name}}`), `minute` and `generation_30s` by its `duration` (`_MEASURED` in `vinci_core.cost`, the same in the Studio's `clipPrice`). With no text or length a job costs `amount`, and so does text that another node makes (a `{{` template stays: its length is not known before the run). The job estimate and the receipt read the job's own inputs, so they price the text and length it sends (COREPRODUC-603). The amounts are ElevenLabs' API prices in US dollars (elevenlabs.io/pricing/api: Flash $0.04 and Multilingual $0.08 per 1,000 characters, sound effects $0.12 and music $0.15 a minute). An account on a credit plan pays in credits, at a different rate for each product: in the paid check of 2026-11-12 (#554), a 62-character Flash line used 31 credits (0.5 a character), a 5 s sound effect 50 and a 10 s music cue 382.

Price check: `scripts/check_wavespeed_prices.py` (needs `WAVESPEED_API_KEY`, never prints it) reads Wavespeed's free usage report and marks each called route that no catalog row matches (`CHECK`, exit code 1). The report shows the billing basis: a call billed as one unit is per clip or picture (the row's amount must be the rate), and a call billed as several units is per second (Kling, Seedance, Wan, InfiniteTalk: the amount must be the rate times the seconds of its unit). A reply with no `per_model_usage` list exits 2. Run it before a release that changes the Wavespeed catalog or plugin (COREPRODUC-595).

Honesty: Magnific sometimes undercuts direct API. Market transparency, choice, $0 monthly floor — never "always cheaper."

## 13. Output destinations (Roadmap #1)

After a completed run (or adapt run), the runtime can mirror each output asset to a user-selected destination. Configuration lives in `~/.vinci/config.toml` under `[output_destination]` and in Studio **avatar menu → Settings → Output saves**. Credentials for cloud buckets are **env-only** (`VINCI_R2_*`); never commit secrets.

| Kind | Behavior |
| --- | --- |
| `none` | Default. Outputs stay in CAS only. |
| `local` | Writes media + `{file}.vinci.json` sidecar to a folder (default `~/.vinci/exports`). |
| `photos` | Stages under `~/.vinci/exports/photos/{album}/` with sidecar; macOS app imports into Photos via `vinciNative` bridge. |
| `r2` | Uploads object + sidecar to the configured bucket prefix using `VINCI_R2_*`. |

Sidecar JSON records prompt, model/provider, params, timestamps, and source ids (`job_id`, `node_id`, …). The `OutputDestination` protocol in `vinci_storage.output_destinations` is the extension point. Roadmap #2 indexes completed runs (CAS/receipts) and those sidecars into a local library.

## 14. Local library / Assets (Roadmap #2)

Every completed run becomes an Assets item. `vinci_storage.library.LibraryIndex` keeps a lightweight SQLite catalog at `$VINCI_HOME/library.sqlite`. The file is created on first ingest, not on daemon start. A fresh home reports `status.reason=empty` until a run completes — destination `none` still indexes CAS outputs.

Write-through: each completed run upserts CAS/receipt metadata (`origin=cas`). A later export overlays sidecar paths onto the same `hash(asset:{asset_id})` row. Scan: `GET /library` and `POST /library/scan` also walk the configured local folder, `$VINCI_HOME/exports`, and `$VINCI_HOME/exports/photos` for `*.vinci.json` files. Scan does not prune CAS rows when a sidecar is missing.

| Endpoint | Behavior |
| --- | --- |
| `GET /library` | Filter by `kind`, `model`, `provider`, `date` (`today`/`7d`/`30d`), `date_from`/`date_to`, prompt `q`, `tool=image\|video\|audio\|enhanced` (Image/Video feed), and `section=assets\|projects\|favorites\|elements\|trash`. Returns `items`, `facets`, `status`. |
| `GET /library/items/{id}` | Detail + rerun hints (`rerun_skill`, `rerun_page`). |
| `PATCH /library/items/{id}` | `{ "favorite": true\|false }` — Higgsfield heart. |
| `DELETE /library/items/{id}` | Soft-delete to Trash. `?purge=1` unlinks local media + sidecar under library roots. |
| `POST /library/items/{id}/restore` | Restore from Trash. |
| `GET /library/items/{id}/file` | Local export file, or CAS fallback for destination=none / remote (R2) rows. |
| `POST /library/scan` | Resync CAS runs + folders and return the same payload as list. |

Studio **Assets** (All tools, Ctrl+K, and the avatar menu — not the icon rail) copies Higgsfield `/asset/all`: sidebar Assets / Projects / Favorites / Elements / Trash + type filters, date-grouped justified grid, select-all per date, prompt/date search. The sidebar and the search bar use the same glass surface as the rest of Studio. Hover menu: favorite, download, copy, Delete (Trash), and — in the Mac app — Reveal in Finder / Save to Photos through the `vinciNative` bridge from Roadmap #1. Image and Video compose pages load `GET /library?tool=image\|video` as their main feed.

## 15. OLF movie engine (`packages/olf`)

`vinci-olf` reads, validates and renders shows in the Open Lore Format (OLF v0.1): a bible, episodes, scenes and shots, and the takes rendered from them. The spec lives next to the code (`packages/olf/SPEC.md`). The package is Apache-2.0; the rest of this tree stays MIT. It sits on top of the runtime: `vinci olf render` resolves a shot, runs an inline `WorkflowSpec` with `Engine.start_run` (keyframe `i2i`/`t2i`, then video `i2v`/`t2v`, or one `tts` node per dialogue line; for an engine move, `camera.render: engine`, the video is a `media` node with the op `camera_move`: `vinci_media.camera` moves the frame over the keyframe with no model, as `local:ffmpeg:v1` at $0), checks the price first, and writes take files with provenance plus lock-file entries. `vinci olf status` compares each take's `inputs_hash` with the current inputs; staleness is never stored. `vinci olf batch` re-renders an episode's stale takes or animates its approved keyframes after one price check. The CLI runs in-process on `$VINCI_HOME` and needs no daemon. A workflow with only local steps (`media`, `indexquery`) starts with no provider connected: only a `generate` node needs one (COREPRODUC-564). The daemon mounts `/olf/*` (sample, project, shot, render, batch, take, select, cut, export, file) when `vinci_olf` imports, and the Studio **Shows** page (rail: Workflows) uses them. It follows the Claude Design editor in the Studio look, keyframes first: the show's header in the Studio top bar, an episode storyboard for review, a full-width shot page that draws and approves keyframes and renders video from the chosen one (price first) and says which level set each look, bible pages with the edit impact, a Shots table, and the Cut screen (preview, timeline, trims and fades, export to 16:9 and 9:16 with subtitles). How it works, the spec changes, and the limits: `docs/OLF_ENGINE.md`. Next slices: COREPRODUC-541 to COREPRODUC-545.
